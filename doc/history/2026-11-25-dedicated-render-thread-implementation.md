# 专用渲染线程实施与验证

记录日期为 2026-11-25。来源为[实施计划](2026-11-24-dedicated-render-thread-plan.md)、本次未提交工作树及本机构建输出。实现、双后端采样和视觉复核均已完成。

- 首次配置发现受管 RadRay 检出与锁文件不一致。检查确认受管工作树干净后，通过仓库的 restore 入口恢复了锁定版本。原有 Debug 依赖清单记录的是旧版本，重新构建独立的 Debug 依赖目录。
- RadRay 的环境会记录创建线程。前端在创建会话时独占初始化资格，工作线程创建和析构环境。屏障等待期间主线程处理 Win32 同步窗口消息，销毁会话后才卸载 DLL。
- 帧槽等待发生在下一批开始或排空时。读回数据保存在工作线程专属的槽对象内，采集后按序发布，Java 同步进度时才写入面向调用方的缓冲。

- 原有线框测试同时发现两种只依赖本批内容的错误延迟到 worker。将复用标志组合与显式可见实例范围校验提前到冻结帧包处。修正后当次 Release nativeTest 通过。关闭编码器时用 Java 资源作用域确保末次 flush 派发异常后仍释放 encoder、renderer 和 runtime。
- 视觉工具默认复制整张地图。新增原地图模式，逐会话隔离元数据、联接原始 region/entities/poi 并启用 Minecraft 自带的禁写区域开关，确保不同后端从相同场景输入开始。
- 使用历史 Tracy/JFR 配置完成首次 Metcalf D3D12 完整运行。nativeCallNs P50 从 0.3617 ms 降至 0.0045 ms，呈现吞吐从 972.42 降至 725.12 FPS，nativeSyncWaitNs P95 达到 1.9626 ms。检查 worker 空闲等待发现显式阻塞 Fence 也依赖 1 ms 轮询。改为前端阻塞时投递硬件 Fence 等待，完成后立即采集并唤醒前端。首次结果保存在独立运行目录，最终对照使用修正版本。

- Vulkan 表面故障测试第一次仅替换一次 `vkCreateSwapchainKHR` 结果，四个 resize 用例均未观察到预期错误。将测试层改成在单次 resize 的调用期间持续注入，由 `finally` 撤销并断言驱动层命中。Release 专项复跑四例通过，覆盖常规重建和表面丢失后新建失败，各自再验证重试或关闭；随后仍需跑全套。
- 对照锁定的 RadRay 源码发现两处上游失败边界。D3D12 与 Vulkan 的非持久映射在底层 Map 失败时会终止进程；截图 Poll 的空返回值检查仅覆盖能返回空指针的实现。Vulkan 的常规 Recreate 会记录创建时的设备丢失，而新建 SwapChain 的失败分支未将 `createResult` 写入设备丢失标志。两种边界均需分别处理和验证。
- 构建目录仅对锁定 RHI 的两个编译单元应用读回与设备丢失补丁，受管检出保持干净。Vulkan 测试层要求专用缓冲分配以避免 VMA 复用已映射大块，然后在完成采集时注入真实 `vkMapMemory` 错误。Release 实测截图映射失败与时间线查询首次报设备丢失均保留上一批水位，失败批的完成回调未执行。另一个专项覆盖新建交换链首次报设备丢失，前端随后观察到设备终态。

- ABI 23 将 `rn_destroy_runtime` 的结果接入 FFM 后，Release 全套 96 项中原有的 `acceptsNullDestroy` 失败。将三个单句柄销毁入口的空句柄处理移到会话门禁前，保留环境尚未创建时的幂等清理。首次创建交换链也补上与 resize 相同的设备终态发布。Release 两项专项通过，其中 Vulkan 在首条 GPU 帧之前返回 `VK_ERROR_DEVICE_LOST`，随后快速查询池创建被拒绝，进度轮询报告设备丢失。
- 一次 Vulkan Newisle 的测量窗口与独立 GPU 测试重叠，排除这次运行。正式矩阵按同一 native 构建身份与客户端源版本筛选。历史系统热点基线与此次线程改动之间还有其他性能改动，另用紧邻重构前的同步实现、相同路线与相同 Tracy/JFR 设置做两后端六场景配对。

- 顶点和索引原先直接暴露池内可写 ByteBuffer，调用方还可移动其游标，改变 worker 读取的首地址。改为独立游标的只读视图，帧包各自持有固定字节范围，消费后逐个解除借用。Release 的 Vulkan 门控测试在 AcquireNext 内暂停 worker，验证改写被拒绝、提前申请释放仍保留数据、Fence 完成后实际归池。双后端线框像素测试还覆盖外部 Arena 提交后立即关闭。
- CTest 原有两项池复用测试仍调用已拆分的创建接口，改为直接观察 Allocate、Register、Take 与退役水位。增加 FakeDevice 的 OnFlush 观测，验证命中映射池的 initial 触发整段刷新，两次脏区间的偏移、长度与顺序匹配，覆盖主机一致内存上仅靠读回字节无法区分的分支。Debug 与 Release 各 28 项 CTest 全部通过。

- 六条 D3D12 正式路线的映射统计中，环形缓冲和暂存顶点缓冲均有写入，普通影子缓冲和 `RayniumTransientMemory` 均为 0 字节。后者在游戏路线内没有写入样本，另用双后端的 `allocateStaging` 写入与读回用例验证。
- 复核等待指标时发现，帧 CSV 的 `nativeSyncWaitNs` 计入 `rn_wait_submit`（包括零时限轮询）。帧队列满时，等待发生在 `rn_submit_frame` 内，已计入 `nativeCallNs`。配对分析从 Tracy 的 `Raynium.Frontend.QueueCapacity` 单列每批 P95，该区间也包含检查空位本身的开销。
- 增补公共 `addView` 的交叉用例。编码器从池中取得 storage，视图描述和网格来自另一个 `NativeFrameBuffer`。在 Vulkan 驱动门控内暂停上一批，本批提交后清零外部可见表并立即关闭其存储，放行后读回的 32 个像素均等于预期。Release 专项 1 项通过。
- C 公共头原有两处注释沿用了调用返回即可释放的旧契约。已在 `rn_submit_frame` 声明处明确默认深拷贝与借用截止水位。正式采样进程加载 DLL 后修正头文件，对比冻结的 181 个构建输入和客户端源文件，当时仅此头文件的注释不同。后续修正了仅在视觉验证模式运行的 VisualValidation，复核同一组 181 个输入，当时变化限于上述头文件和视觉驱动。最后一次复核另有 NativeRenderer 的关闭修正。该处以在途批次判断是否需要排空，性能采样覆盖的逐帧路径仅作同一队列字段改名。

## 正式采样

两后端各六条路线共记录 2,376,307 行 Java 帧，完整 GPU 帧样本同为 2,376,307。映射脏区间按字节累加，MAPPABLE_RING 为 12,380,251,368，STAGED_VERTEX 为 565,366,659,940，HOST_SHADOW 和 TRANSIENT 均为 0。每条路线各有一份 Tracy 和一份 JFR，运行目录见本机 `build/benchmarks/dedicated-render-thread/selected.json`。

### 配对结果

i7-13700K、RTX 4080、1920×1080，渲染距离 32、模拟距离 8。线程版与紧邻重构前的同步版各跑 D3D12、Vulkan 六场景，均用 Release、Tracy 0.15.0 与 JFR，实测均选择 indirect 地形提交。每组正式测量一轮，Newisle 为 60 秒，其余为 240 秒。基准直接打开原存档，游戏正常写回，单轮差值包含模拟状态和运行顺序的影响。

| 场景 | D3D12 同步 → 线程版 FPS | Vulkan 同步 → 线程版 FPS |
| --- | ---: | ---: |
| Metcalf | 941 → 1064（+13.1%） | 963 → 1031（+7.1%） |
| Tideworn | 716 → 802（+11.9%） | 741 → 805（+8.7%） |
| Newisle | 262 → 369（+40.5%） | 289 → 387（+33.9%） |
| 实体 | 654 → 908（+38.8%） | 650 → 926（+42.4%） |
| 粒子与透明 | 351 → 472（+34.5%） | 366 → 505（+38.0%） |
| 背包 GUI | 1204 → 1519（+26.1%） | 1378 → 1678（+21.7%） |

12 组的呈现吞吐均提高，主线程渲染墙钟 P95 均下降。按每个场景的比值等权取几何平均，D3D12 吞吐提高 27.0%、主线程渲染 P95 下降 26.1%，Vulkan 分别为提高 24.5%、下降 24.8%。相对 `system-hotspots` 的历史联合录制，吞吐分别提高 30.2% 和 35.2%，其中也包含 11 月 24 日已落地的优化。完整分位数和逐场历史值在本机 `build/benchmarks/dedicated-render-thread/comparison.md`。

- 12 场都观察到主线程与 worker 的工作区间重叠。用相同提交序号对齐两个时钟，210 个窗口均可校准，在 worker 构图、准备或录制期间取得 1,486 个 MC 主线程 Java 执行样本。主线程 native 预检与 worker 的上述区间另有 49.44 ms 墙钟交集。Tracy 测量窗口内 2,376,295 次 Present 均在 worker 上。部分场景仍受显式等待影响，例如 D3D12 Metcalf 的 `rn_wait_submit` 每帧合计 P95 从 0.239 ms 升至 0.747 ms，而主线程总渲染 P95 从 2.106 ms 降至 1.585 ms。
- 历史热点中的粒子碰撞和调色板查询仍占两后端渲染调用外 Java 执行样本的 57.9% 和 61.0%。线程版粒子帧间隔 P95 已降至 2.451 / 2.247 ms，但每秒仍各有 20.4 次帧间隔超过 5 ms，P99 为 8.61 / 8.74 ms。Newisle 的可见方块实体提取仍占慢渲染帧 Java 执行样本的 13.5% / 15.2%。

## 构建与测试

收口时又核对了计划点名的边界。原静态网格用例两次都落在第 0 页，新增经 C ABI 先交一帧、删除并重传同一大网格的双后端用例。表面粘滞恢复的首轮实机测试试图在丢失的 Vulkan 交换链上注入下一次获取超时；上游已锁存表面丢失，没有再进入驱动获取，实际结果仍为 `SURFACE_LOST`。改为先通过驱动注入真实丢失，再隐藏窗口，让下一批走正常的 `SKIPPED` 分支，两次 C 快照都不提前派发到 Java。另将带 GPU 时间的离屏清屏批与后继上屏批放入同一次 ABI 数组读取，并在排空屏障等待中注入设备丢失。

直接关闭离屏 Java renderer 时，旧判断只检查待消费的借用输入。GPU 门控用例先观察到提交回调执行、完成回调仍未执行，再放行 GPU 并直接关闭 renderer。原实现跳过排空，完成回调次数为 0。改为按尚未观察到完成的在途批次判断关闭时是否排空，回调在映射关闭前读到 `0x12345678`，执行次数为 1。修正前失败报告与最终双配置报告分别位于本机 `build/validation/dedicated-render-thread/close-before.xml` 和 `tests-final`。

最终 Release 与 Debug 均为 Java 单测 78 项、双后端 nativeTest 100 项、Vulkan 驱动故障测试 27 项、CTest 28 项通过，JUnit 跳过数为 0。两后端实测重传取得第 1 页，两个连续测量批各有一条非零 GPU 时间。Vulkan 在实际窗口隐藏后保留同代丢失状态，重新配置后连续两次呈现使计数累加 2，重复轮询的计数相同。门控 GPU 测试还直接读取了重写槽未完成时的 C 样本序号 0，完成回调从映射中读到新字节。Release 开启驱动校验和 Tracy，Debug 开启 RHI 包装层和驱动校验。最终日志、XML 和专项方法报告位于本机 `build/validation/dedicated-render-thread/tests-final`。Python 工具测试 17 项通过。

## 视觉验证

基准的实体、粒子和背包路线在原存档留下了 49 × 49 的光滑石平台。首个原版视觉会话在铺设较小石台时得到 Minecraft 的零修改失败。复核 82 个源区域文件的内容和修改时间，失败会话未改动它们。后续在各会话的禁写区块内先移除基准平台。字体场景自带的 `clear @s` 也会在空背包上返回失败，因此先放入一个临时物品，再由场景原有命令清空；缺少清空命令的场景由前置步骤清空。保留全部原始布景命令。实际输入与场景名、时长、画面和差分报告一同保存在 `build/validation/dedicated-render-thread`。

原版、D3D12 与 Vulkan 各完成 11 个套件、86 个场景，含导出物各 123 张图。双后端共 246 组对比，以任一 RGBA 通道差值大于 2 标记像素。本轮 123 组全部像素在阈值内，历史验证为 181 组。按每张图的位置比对历史差异，112 张出现过新的超阈值像素，其中 64 张的新增像素全部位于 y=310 同一行。用重构前同步版、当前布景和本轮原版截图补做同场景对照。

在出现新增差异的位置所属的 19 个“套件 × 后端”上另跑紧邻重构前的同步实现，覆盖 232 组对比。原版 `night-sky` 的天空光照系数为 1.00。检查 Minecraft 26.3 源码，视觉脚本设置的 `ClientLevel.setTimeFromServer` 只改 `gameTime`，`ClientClockManager` 单独维护太阳所在的世界时钟。诊断会话在临时世界执行 `gamerule minecraft:advance_time false`，并保留场景指定的 `time set`，原版同场景系数为 0.24。D3D12 的 `world-border` 在原输入上有 378 个线程版与同步版直接比较超阈值的像素，固定世界时钟后为 0，两者相对原版均为 72 个。相同控制下 `post-creeper` 的两版直接差异由 248 个降至 0，`materials-oit` 的两版相对原版均由 1,551 个降至 429 个。原始图与控钟对照分别见本机 `build/validation/dedicated-render-thread` 下的主矩阵和 `solar-control`。

固定时钟的五组完整对照使用同一视觉驱动，分别运行原版、紧邻重构前的 D3D12 与 Vulkan、线程版的 D3D12 与 Vulkan。55 个会话各自核对场景时钟，44 个原生会话同时开启 RHI 与驱动校验。11 个套件、86 个场景、每组 123 张图全部产出。同后端新旧版直接比较，210/246 组的所有像素均在通道差值 2 以内。分别与原版比较，线程版为 179/246，同步版为 173/246。effects 的 62 组、资源动画与纹理导出的 60 组均在新旧版直接比较中全部符合阈值。

其余 36 组中有 20 组属于常规套件。图库及透明排序出现差异的位置落在时钟物品图标内，例如 Vulkan 图库 32 个像素、Vulkan 透明排序 60 个像素，其线程版颜色均已在同坐标的重构前 Vulkan 截图中出现。Minecraft 的时钟物品根据上次更新的角度和速度选择下一个模型，固定太阳时刻仍保留进入场景前的角速度。Vulkan pause-blur 的 69 个像素同样匹配旧版截图；Vulkan 高对比描边的四张线程版图均已与原版一致。逐像素追溯见本机 `build/validation/dedicated-render-thread/clock-matrix/historical-attribution.json`。剩余 16 组集中在特殊实体套件，对其另做姿态对照。

特殊实体套件用诊断模组在 Minecraft 模型抽取结束时记录原版的动画输入，随后在独立的原版、同步和线程版进程中重放。两轮均保留 9 个场景与原有实体，清场时临时关闭掉落。第一轮固定幻翼振翅和守卫者尖刺、尾部动画，D3D12 的 9 对图片全部落入阈值；Vulkan 的剩余差异还涉及旋风人动画和幻翼日间着火。第二轮也重放这些输入和狼的姿态，五个重放会话一共核对 160 组实际模型状态。Vulkan 仍有 5 张图各出现 17 个新旧版直接差异像素，两次原版在相同位置也有这 17 个像素的变化；逐张对当次原版比较，线程版的超阈值像素为 1 个，同步版为 18 个。D3D12 仅龙死亡场景的末地折跃门光束区域存在 220 个直接差异像素，其中 219 个线程版像素与历史原版完全相同，另一个最大通道差为 1。

在 86 场景、双后端与既定阈值内，未发现可归因于专用渲染线程的新增像素回归。原有后端差异仍可见，例如固定时钟下 D3D12 经典线框的两种实现直接一致，相对原版均有 55,124 个超阈值像素。原视觉存档的 82 个区域文件共 197,726,208 字节，复核前后内容和修改时间一致，134 个临时会话存档均未留下区域副本或联接。视觉总结与原始逐图核查分别在本机 `build/validation/dedicated-render-thread/visual-comparison.md` 和 `final-visual-audit.json`。
