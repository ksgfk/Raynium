# 阶段二实施记录

2026-11-21 开始。基线为当日 `develop` 工作树、ABI 18 和仓库锁定的上游版本。

## 受管检出偏离锁文件

开工时 `python tools/fetch_radray.py status` 报告版本不符。受管目录工作树干净，处于 detached HEAD，本地对象库缺少锁定提交。独立的上游开发仓库已有该对象。

从上游本地仓库 fetch 锁定对象后，执行 `python tools/fetch_radray.py restore`。再次运行 `status` 已匹配锁文件。整个过程沿用受管目录的原 origin 和现有锁文件。

## ABI 18 基线的 Debug 依赖身份

恢复锁定版本后，Gradle 的 Java `test` 为 up-to-date，`nativeConfigure` 因已有 Debug 依赖的版本标识与锁文件不同而中止。使用 `tools/build_debug_dependencies.py` 按恢复后的源码重新准备专用 /MTd 构建目录，再重试原生基线。

依赖重建后，Gradle 已能配置、构建并运行 112 项原生测试。首次运行有一项 D3D12 计时测试在 `NativeSceneTest.java` 的正时长断言失败，完成序号断言通过。单独复测同一测试的 D3D12 和 Vulkan 参数均通过。首次结果保留为基线观测，原因尚未确认。

随后以原命令重新运行完整 `test nativeTest -PrhiValidation=true`，Gradle 成功，全部原生用例通过。

## 升级后重新验证设备能力和完成序号

锁文件升级后，重新准备匹配源码的 Debug 依赖。设备能力查询同时扩展了 C 结构和 Java 布局，提交等待读取图形队列最后确认的完成值。无限等待分段调用带超时的 Fence 接口，使设备丢失时能够返回调用方。升级后重新执行 `gradlew test nativeTest -PrhiValidation=true` 通过。

## 同纹理非重叠拷贝与录制期间关闭纹理

帧图以整张纹理跟踪复制源和目的状态。对于同纹理内合法的非重叠区域，先把源区域拷入同格式瞬态纹理，再写入目的区域；重叠的同一子资源在 Java 写入命令前拒绝。录制时持有纹理引用，应用先关闭纹理时延迟移除原生 ID，提交返回后由帧槽内的图资源继续持有 GPU 对象。

无窗口真设备用例在同一批次中读取局部清除前后的像素，覆盖非零 mip 和数组层、自拷贝、带行距上传、提交前关闭纹理、无限等待和紧随其后的空提交。D3D12 与 Vulkan 的四个参数化用例全部通过，其中两项验证无效命令流使后续提交失败且不产生完成序号。

## SDL 上屏裁剪与次优状态

旧输出程序始终读取第零级并按屏幕坐标直接取样。命令流上屏现在显式绑定源 mip，以源和窗口尺寸中的较小值设置视口与裁剪范围，并把实际拷贝高度传给像素着色器用于逐行翻转。交换链外围清黑。重新编译了默认双后端着色器包。上游可把 Vulkan 次优呈现映射到 RequireRecreate，因此先识别原生结果，再区分下一帧重配与当前帧跳过。SDL 真窗口已验证连续离屏、上屏、离屏提交按批次绑定表面。

## 同批多次写入同一逻辑时间戳

同一个逻辑查询在一批内可以写入多次。每次写消耗独立物理槽，帧尾一次解析全部槽。每个帧槽独立持有查询池和持久映射的读回缓冲，Fence 完成后按写入顺序发布，仅更新仍指向该序号的逻辑槽。Java 在录制时即关联新批次，使取消的批次也能屏蔽旧值。双后端定向测试已验证重复写入、跨两个帧槽复用、空结果和越界拒绝。

## 按提交序号发布紧凑缓冲结果

两个帧槽轮转后，物理槽下标和提交先后次序可能相反。现在按提交序号收割已完成帧槽，每槽只失效自身的读回暂存映射，再按录制顺序发布内嵌字节和 GPU 结果。回调在 Java 返回 Fence 成功前排出。持久可写映射尚未关闭时也随提交刷新。设备缓冲的局部可写映射自持精确长度的暂存，在关闭时写入当时的批次。

D3D12 与 Vulkan 已对照实际字节验证长驻映射、跨批次局部写回、自拷贝、带偏移及行距的双向颜色传输，以及奇数宽 D16 整子资源纹理拷贝和深度读回。不满足设备行距的布局按行重新打包；主机目的和设备目的均保留调用方紧凑布局。

## 首次部分写入与深度初始化

纹理第一次用于局部写入时，后续可能读取其他层和 mip。首次导入现在按创建标志选择附件清除或零字节上传，逐层逐级初始化。仅有一个子资源且本次操作完整覆盖它时省略初始化。D3D12 和 Vulkan 已验证非附件 D16 深度纹理首次读回为零，以及只上传一个 mip 后其他层仍为零。

## 可测的 GPU 工作量

旧定时测试只在很小的渲染目标上执行快速清除，同一硬件计时刻度内起止可能相等。用例改用 1024 × 512 目标并请求整帅读回，保留正耗时断言且核对读回的提交序号。双后端定向复测通过。

## 着色器包含文件的字节长度与跨后端反射

运行实际管线目录时，同一份片元源在先后两次编译中出现了不同哈希。MC 使用不带结尾零字节的 UTF-8 创建 include，LWJGL 的 content() 访问器却按零结尾字符串扫描。现在按 shaderc 结构中明确的 content_length 读取定长字节。离线编译另外保留跨阶段一致的常量块布局，以优化后的 SPIR-V 识别活动资源，以原始顶点接口覆盖 DXIL 保留的输入语义。默认包使用程序清单文件传参，避免 Windows 命令行长度限制。

## 图集尺寸与无符号设备上限

RTX 4080 的 Vulkan 驱动将单次分配上限报告为 UINT64_MAX。原样读作 Java long 后成了负数，DeviceLimits 计算出的图集边长为零，加载画面无法进入世界。FFM 现在把超出 Java 正数范围的容量饱和为 Long.MAX_VALUE。双后端前端测试增加 RGBA8 图集尺寸断言。

地形视图只保存相机与几何快照。每次 renderLayers 调用另外记录其实际图集与光照视图、mip 范围和两份采样状态，使同一快照可以供不同材质绑定的 Pass 使用。

## 资源包程序缓存与 Push Constant

程序缓存以源码和宏的完整 SHA-256 为键，后台任务校验反射与双后端包指纹后原子发布单个 ZIP。没有缓存时可通过 raynium.shaderToolsDir 指定离线转换工具。阶段二工具包由 python tools/compile_shader_pack.py --install-tools 生成。编译与读缓存均在 taskExecutor 上执行，所属线程在 finishCompile 注册管线。不同管线对同一程序分别校验绑定和 Push Constant 大小。

SPIRV-Cross 输出的无寄存器 cbuffer 不能直接通过 RadRay 双目标编译。转换器保留寄存器内的实际偏移，生成 Vulkan push block 和 D3D12 root constants，使用相同 register 注解。双后端实测先绘制全绿，再局部推送蓝色，读回像素符合预期。覆盖原版地形着色器时按原版宏组合回退并给出一次提示。

## 帧管线与资源包清退

首个可运行版本同时加载旧场景包与即时程序，共 277 项。清退旧场景和 GUI 录制后，ModularFramePipeline 直接回放命令流，默认包缩减为 139 个程序，大小由 5,873,458 字节降至 2,914,150 字节。六个常驻地形程序保留，其余光照图、动态纹理、GUI 和后处理由原版光栅 Pass 驱动。地形视图描述符缩至 280 字节，截图和字体不再需要接管 Mixin。视觉验证的动画时钟仍直接读取帧序列，因此保留它实际使用的 SpriteContents 访问条目。

同一游戏帧可能分多批提交。基准按批累加实际上传、绘制、CPU 分段与 GPU 时间，处理完成的上屏批次时发布整帧 GPU 样本。测试中的接管专用帧结构已移除，交换链、捕获短缓冲和跨页线框几何改为从命令流执行。

## 多视图、Push Constant 与 ABI 版本

MC 接受剩余字节多于管线声明大小的 Push Constant 视图。旧录制会把额外字节一起复制，并在 native 上误触 128 字节检查。现在按管线声明的范围复制，编译时按设备上限校验。同一个 Pass 中先画绿色，再逆序回放六个独立地形视图，最后通过原管线再次绘绿。双后端逐像素核对了中间六行的不同材质颜色和两侧即时绘制。每管线的有类型纹素缓冲也按导出格式和 sampler 数值类型校验。代码、载荷清单与加载器采用 ABI 19，并在绑定新导出前拒绝旧 DLL。

## D3D12 着色器的顶点与实例起点

在 clip.w=2 的离屏绘制中，用非零 firstInstance 改变顶点绕序。Vulkan 按预期切换正反面，D3D12 在第二条命令仍画出了正面。SM 6.0 的 SV_InstanceID 与 SV_VertexID 不包含调用起点。转换器现为读取这两个输入的 DXIL 程序增加内部常量绑定。直接绘制从命令取得起点，间接绘制通过图中的 GPU 拷贝提取实际参数的末两个字，在对应记录前重绑。Vulkan 保留原生内建输入。缓存目录版本升到 v2，旧编译产物不会误命中。双后端直接、间接和索引间接绘制均验证起点、剔除、片元行号、W 倒数及有符号纹素；修复后内置包为 2,930,854 字节。RHI 验证还检出组布局早于依赖它的管线布局析构，将所有组布局置于管线布局前声明后按正确顺序释放。

## 并行采集与构建产物

两个独立 Gradle 调用同时重新配置同一个 Debug Ninja 目录时，Windows 拒绝重写构建日志。先单独执行 nativeStage，核对已发布快照的 ABI，再用 nativeTest -x nativeStage 运行该快照的测试。更改纹素反射 JSON 期间启动的旧字体采集混用了两版产物，已在新包生成后重新运行；两端分别完成六个字体场景。

## Vulkan 后处理的未绑定常量块

19 场景的客户端完成了采集，但 Vulkan 验证在 post-creeper 和 post-invert 报告参数表缺少资源。比较最终包与即时接口发现，两个后处理程序及闪电 OIT 的 SPIR-V 仍包含只在死表达式中读取的常量块，而优化后的 GLSL 活动接口已去除它们。离线转换现将两阶段均不使用的块替换为本地常量，保留跨阶段布局与表达式，再编译最终 artifact。新增验包断言逐个核对每个程序的 DXIL、SPIR-V 物理绑定与 Java 能提供的槽位。最终包为 139 个程序、2,930,430 字节。

## 船舱水面遮罩

全场景差图中普通水面的 Vulkan 船舱出现 2,990 个超差像素，白色区域正好贴合遮罩几何。WATER_MASK 为深度写入启用颜色附件且将四通道写掩码设为零。上游 Vulkan RHI 遗漏零掩码及部分组合，已按完整四位集合修正。保留原版管线和片元着色器。复采后普通和 OIT 船舱的全图最大通道误差都为 1，超差像素数均为 0。

## 终态后的表面获取

同一设备创建第二个尚未配置的表面时，其前端对象的创建与关闭原会替换或清除已用交换链的终态回调。现在由成功创建交换链的表面登记及解除回调。帧头获取先检查渲染器状态，旧 Fence 报告设备丢失后再次获取立即失败，前端获取标志仍为假。测试覆盖关闭未配置表面后触发丢失和实际 C ABI 销毁。

## 地形视图暂存的复用时机

Metcalf 压测暴露了每个视图每帧重新分配可见记录与实例数组的成本。每个编码器现在复用已结束提交的视图暂存，同一批内的多个视图各自占用一份。原生提交已将描述与数据复制到自己的帧槽，Java 可以在等待 GPU 前再次使用这块内存。编码器关闭时统一释放闲置暂存。定向测试在第一次提交和围栏等待之间复用首个缓冲并提交新快照，再读回第一批的六个视图。

## 双后端图像与管线覆盖

11 组共 86 个场景在原版、D3D12 和 Vulkan 下完成采集。包含图集等中间产物后，每个后端各比较 123 张图。以每通道误差 2 为阈值，D3D12 有 75 张、Vulkan 有 105 张全图达标。D3D12 普通和 OIT 线框均有 55,078 个超差像素，同一场景的阶段一数值分别为 55,012 和 54,961。Vulkan 对应两帧为 175 和 124。已逐组查看三方并排图，保留线框与高对比轮廓的原始差异。

195 条原版管线与 5 个后处理链通过清单、双后端着色器及源码路径校验；场景实际记录了 154 条管线和 3 个显式后处理请求。逐图统计与本机复核结果存于 build/validation/phase2-final/visual-review.md 及同目录 pipelines.json。

## 地形插入后的绘制状态

地形、即时绘制与查询打点需要在同一打开的硬件 Pass 内保持顺序。逻辑 Pass 用有序命令保存三者，由 ImmediateDraw 与 TerrainFeature 分别声明依赖、准备参数并录制。每笔即时绘制保存完整状态，地形返回后恢复视口和裁剪，后续绘制按自己的快照绑定 PSO、参数、常量和几何。每个已注册管线按深度附件格式缓存自身的 PSO 变体，参数集在帧槽复用。这样保留了原计划的模块边界，也避免向这些命令提供空的共同虚方法。

## 在原生设备入口重现提交故障

最初的 FFM 故障测试能验证 Java 对返回值的处理，但设备本身仍可能处于健康状态。新增独立的 Vulkan 测试进程，在真实驱动调用处注入结果，从时间线查询、瞬态纹理创建、队列提交、呈现及旧围栏等待五处观察设备丢失。已上队的批次先登记寿命，未上队的批次保持零序号。每条丢失路径均在真实交换链和渲染器销毁前完成单次原生 idle。测试只修改返回值，保留物理设备。Windows 加载器需要测试层清单使用实际 DLL 路径，清单随本机测试构建生成。

同一测试进程覆盖获取次优、获取或呈现时交换链过期与表面丢失。首次地形上传、读回、查询及围栏均在表面降级时完成，重建交换链后以同一网格绘制。用时间线信号量阻住第二批 GPU 工作时，第一批的只读映射与查询槽均已可见，第二批紧邻的字节与查询槽在放行后才发布。

## 两张地图的整帧基线

RTX 4080，Release，1920 × 1080，视距 32、模拟距离 8。各配置顺序运行一次，每次预热 60 秒，测量完整 240 秒路线。下表为帧间隔的 P50 / P95，单位为毫秒。阶段一 D3D12 取同地图、路线、设置及后端的阶段一主测记录。

| 地图 | 阶段一 D3D12 | 阶段二 D3D12 | 阶段二 Vulkan | 原版 Vulkan |
| --- | --- | --- | --- | --- |
| Metcalf | 1.4254 / 5.5894 | 1.9399 / 7.0132 | 1.8034 / 6.8320 | 1.1536 / 4.2941 |
| Tideworn | 2.9136 / 7.2785 | 3.9210 / 9.1163 | 3.7638 / 8.8996 | 2.1729 / 5.3406 |

Metcalf 在复用地形视图暂存前，D3D12 和 Vulkan 的 P50 分别为 2.1211 和 1.9499 毫秒。复测时两者均有下降。与阶段一主测相比，阶段二 D3D12 的帧间隔 P50 在两图分别增加 36.1% 和 34.6%，同期 GPU 样本中位数从 0.637 到 0.683 毫秒、从 1.079 到 1.083 毫秒。两张地图的原版 Vulkan 整帧时间均低于阶段二原生后端。

## 最终构建与测试结果

47 项 JVM 测试通过。Debug 与 Release 各通过 82 项普通 Native 集成测试、12 项 Vulkan 驱动故障与在途队列测试、35 项 CTest。两种配置均启用 RHI 验证运行集成测试。14 项 Python 工具测试全部通过。保留的 JUnit XML 位于 `build/validation/phase2-final/test-results/`。

重新打包后的 Windows x64 Release JAR 通过结构与哈希校验。ABI 为 19，内置着色器包含 139 个程序。Debug 快照使用 `/MTd`，Release 分发使用 `/MT`。分发清单只含 `rayniumruntime.dll`，并关闭了 Tracy。
