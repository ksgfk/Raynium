# Raynium 文档维护

在 Raynium 仓库工作。先读根 `AGENTS.md` 和 `doc/architecture/overview.md`，再按任务读取所属文档及代码锚点。
调整文档组织或归档时，从仓库根读取 `doc/guide/documentation.md`；历史导航按需读 `doc/history/README.md`。
本技能中的仓库路径从根目录解析，不使用机器绝对路径或跨目录 Markdown 链接。

## 当前事实与历史的边界

- 除 `doc/history/` 外，仓库文档只记录当前源码、配置、锁文件及现行规则可核实的事实：已实现行为、接口、所有权、当前测试覆盖和可执行步骤。
- 单次构建、测试、验收、游戏运行、采样结果，以及开发经过、阶段总结、旧实现与旧配置记录，全部归 history；操作指南不保留“当前验证摘要”或按日期累积的结果。
- 计划、目标设计、建议、推断、候选方案、未来接口和未实施验收计划也只归 history。用户确认或加状态标签不等于已经实现。
- 当前能力缺口可以按源码说明现状，不附实施安排。必要设计理由必须对应现有实现；当前依赖源码/API 事实须注明版本和来源。独立第三方模组调查、跨版本比较及选型分析归 history。
- 历史报告、旧测试通过结果和外部 checkout 不能单独证明当前行为或测试覆盖。逐项核对声明与当前实现，修正不符内容；有授权归档的旧记录先保存再清理。

## 归属与更新

- 根 AGENTS 保留跨任务约束和少量入口；不借整理改变工程行为或引入无关开发规则。
- `doc/architecture/` 维护当前结构、职责、接口与生命周期；overview 只维护当前地图和入口，不展开历史条目。
- `doc/guide/` 维护当前操作、测试方法及结果查看方式；README 只介绍项目现状和入口。
- `doc/history/README.md` 是独立历史索引，可随新增记录更新；其余历史记录和附件冻结。项目技能放在 `.agents/skills/`，不修改用户全局技能。

1. 检查工作树，保留用户改动；按本次范围读取引用和所属源码，不预加载整棵文档树。
2. 同一当前事实只维护一处权威说明，其余给摘要和链接。术语在所属页面首次使用处解释，必要理由紧邻约束。
3. 删除、合并或迁移前核对引用与独有内容。获授权的历史材料先归档，再清理当前页面；保留原有命令、环境、结果、限制和证据来源，不改写成当前保证。
4. `doc/` 页面使用“适用、权威、锚点”三行头部，锚点填写实际存在的仓库相对路径；根 AGENTS、README 和 SKILL 不套此格式。历史索引仍使用页面头部。
5. 页面引用用相对链接与仓库代码锚点；MC 来源注明版本、类/方法和源码生成入口，不以个人目录或忽略缓存的链接充当唯一证据。RadRay 精确版本以锁文件为准。
6. 变更归属时同步 overview、AGENTS、README、技能和源码入口；移走章节后修复当前引用，不回写已有历史内的链接和锚点。

不另建词汇表、ADR、研究档案或计划目录；未获授权保存的讨论留在会话。
除非用户明确要求，文档（含 history）不保存 Git hash，包括完整值、缩写和链接 URL 中的值；用日期、版本、来源路径和状态说明背景。

## 开发历史

默认不新增历史记录。普通实现、重构、测试通过、日常文档同步和整理目录本身都不构成保存授权。
用户明确要求或同意保存计划、思考、开发经过、实验、验收、采样、快照或交接，或授权迁移已有记录后才写入；已有授权直接执行，不重复确认。
认为有保留价值时可以简述拟保存内容与理由后询问，未回复不阻塞其他工作，也不将内容暂存到 architecture/guide。

归档细节按 `doc/guide/documentation.md` 的“开发历史”执行：文件使用 `YYYY-MM-DD-主题.扩展名`，日期沿用原材料日期或用户指定日期，
注明状态、范围、来源与归档日期；来源含未提交工作树时明确说明。区分用户目标、助手建议、原文结论与实际验证，不以归档声称重新执行检查。
按日期或主题独立的原记录分别建文档；保留理解当时过程所需的职责、数据流、所有权、寿命、取舍及限制，再清理来源页。
新增记录后更新 `doc/history/README.md`，overview 和根入口只链接该索引。索引是日期命名和历史冻结规则的唯一例外。

已有历史记录和附件不修改、不补注、不改名、不删除；实现演进只更新当前所属页面。
历史中的旧路径、接口和链接按记录日期、版本及来源理解，不为通过当前检查回写历史。

## 完成检查

在仓库根运行 `python tools/check_docs.py` 和 `git diff --check`。
核查当前命令、类型、开关与文件一致，确认 architecture/guide 没有历史运行结果、开发日志、计划或未实施结论。
核对迁出内容完整、已有历史未改动、本次没有加入未经明确要求的 Git hash。
历史正文只检查文件命名和页面头部；历史索引以及当前文档、入口、技能和源码中的引用按当前工作树严格校验。
修改检查器时验证缺失引用能被拒绝。检查脚本不能代替技术事实核对。
纯文档整理无需构建游戏；汇报实际改动和本次检查，不把旧运行结果写成本次重测。
